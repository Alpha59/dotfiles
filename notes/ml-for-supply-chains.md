# Machine Learning for Supply Chains

Machine learning is the augmentation of human processes using computer models which are trained to analysis a set point of data, and determine the most statistically accurate outcome to a pre-defined question.

### Why Machine learning?

 Why Machine Learning in Supply Chain Management?

* Historical Data Analysis
* Market Specific Trends
* Promotional Activities throughout the Market

 Machine Learning can increase the cost effectiveness of the Supply chain by optimizing for situations that require too much data for a human to process. It can reduce the amount of human staff and man power required to intervene in every aspect of the supply chain, and real time data allows instant response to supply chain vulnerabilities.

 Traditional supply chain modifications rely on root cause analysis and Post-mortem data analysis to identify gaps in the supply chain life cycle. Machine Learning allows companies to proactively examine their transactional data, in near real time, and use the insights to reduce the revenue loss associated with traditional supply chain bottle necks. This impact can be as high as a 10% reduction in losses.

 The largest losses in supply chain can come from:

* Inadequate inventory to fulfill demand
* Supply shortages or logistical uncertainty
* Backlog and Canceled orders due to backlog
* Gaps in communication and loss of revenue due to operational delays

 All of which are difficult to predict in real-time, and can be even more difficult to predict using pre-defined models, due to the number of data sources required, and the unpredictability to how various factors interact with each-other. Replacing manual judgement that have previously been considered the cutting edge of the supply chain optimization process with data-driven machine learning can pave the way for sustainable supply chain processes that continually adapt to changes.

### How can Machine Learning Help?

 Machine learning can be utilized to identify the root cause of returns, by utilizing data from shipment, transportation, and original orders. This form of machine learning is useful for optimizing the forward logistics arm of the supply chain. By utilizing data visualization throughout the process, additional insights may be gleamed from human interaction - which can often spot larger picture differences, or provide context that a machine learning algorithm does not have access to.

 Utilizing machine learning in the Returns Process can ensure that identification of issues is forecast based, and not diagnostic in nature. The growth in data volume and diversity within the supply chain realm is often considered to be impractical or impossible to manually manage. As the number of products available, and the number of factors dictating the supply chain performance increase exponentially, the use of predictive analytics becomes imperative to success.

 One key aspect to the success of a supply chain ML system is the adaptability of the individual actors within the supply chain. Forecasting supply chain is both a long-term and a short-term plan, which requires that the supply chain be able to adapt to predicted changes when they are forecasted. This means that not only do the predictive analytics need historical knowledge of the system, but they also need the ability to readily adapt various aspects of the supply chain process. This will allow for the best optimization of procedure within the supply chain. Although static shop floor control is often beneficial in the hard-coding of shop floor procedures, a shop floor control which allows for changes and configuration based on the added data driven analytics allows increased efficiency and performance to avoid bottle necks.

 Machine learning aims to reduce the supply chain disruptions, ensure proper inventory levels, and reduce the number of corrective measures that need to be taken. This in turn is dependent on forecasting future sales, return volume, and required refurbished sales volumes. Within the supply chain, different algorithms can feed into each-other. A single algorithm used to predict future sales can become an input to the prediction of return volume, or refurbished sales. Likewise, return volume forecasts can be used to predict the number of new product sales during a new product launch.

 Within the actual supply chain, additional ML can be utilized, like identifying incorrect RFID scans, or identifying discrepant return information.


## Aspects of Machine Learning

 Machine learning is a subset of artificial intelligence, and represents a different approach to programming problems. Opposed to rigid calculation and analysis, Machine Learning focuses on the use of historical or example data to create a statistical regularity model. These models are then used to react to new data, and classify unknown categories of data into the predictive model. This methodology allows for gradual changes and adaptations to the model, without human intervention.

 Within Machine learning, three separate branches of learning can be utilized. Supervised, unsupervised, and reinforcement. The basis of the difference between these three models is the configuration of the input data. Data which is pre-configured with the “solution” is considered to be supervised. Data in which the proper “solution” is not previously determined is known as Unsupervised, and Reinforcement learning is performed when the solution is only known to the algorithm after the “solution” is predicted.

 Collecting and cleaning data, as well as combining data from all relevant sources is the first step in a machine learning algorithm. Although not all data sources may be useful in predicting the outcome, or forecasting the market trends, the use of multiple data sources can ensure that data is not lost, overlooked, or misidentified. Data must then be classified based on if it is a dependent, or independent factor in the unique problem statement being identified. A robust ML algorithm, such as random forest, support vector machine, or gradient boosting can then be used to train the transactional dataset in order to identify the likelihood of a desired outcome.

 It is important to note at this point, that the outcome to a machine learning algorithm, or the “solution” is never considered as 100% accurate, and most predictive algorithms produce a probability of correctness. Using this probability of correctness as a threshold, the solution can then be accepted or denied. This allows continued human intervention in the Machine learning process, so that incorrect data does not move into the production environment. This continued human intervention, and adaptation of the correctness threshold is a good way to ensure quality, while also increasing business trust in the machine learning algorithm’s success.

### Cognitive Automation

 Although Cognitive automation is often considered as a branch of AI, it is strictly speaking a subset of programming which is not encompassed by AI. Cognitive automation refers to the process of replacing clerical labor, or processes which have defined inputs and outputs, and creating a non-adaptive model for those inputs and outputs. Although the model will often account for statistical differences in the input, or numerical values used to calculate the most efficient output - the model is still defined using a combination of business requirements and programmer intervention. This execution of rule based work-streams is beneficial in some aspects of development, but is often mistaken for AI.

 In some cases Cognitive automation can replace 90-95% of an employees job, especially when those jobs include a series of repetitive tasks. Cognitive automation is currently applied at large in the Robotics Automation and manufacturing industry, helping to reduce the number of laborers required to produce or act within the supply chain. Although these processes are certainly beneficial, they are best suited for well defined tasks.

 These systems are not ideal for supply chain management, because they require the additional management of themselves. Although they work well for non-adaptive processes, they are not able to learn or adapt to changes in the environment. True AI requires the ability to not only mimic human decision making, but also adapt the decision making process based on new information. These systems can often work well in tandem, where Cognitive automation can be used to collect and gather data for a Machine Learning algorithm.

 Developing cognitive automation for configuration data is often a more time consuming process than producing a machine learning algorithm. At the same time, cognitive automation is a highly error prone task, with the initial knowledge base spread across numerous conflicting human sources. The maintenance of cognitive automation tasks must also be continually improved, requiring dedicated development time to ensure that the process can be updated based on new or changing information.

### Workflow Management

 The workflow model is defined as the explicit representation of the business process, and the definitions for how the business processes, or supply chain steps need to be executed. Traditionally, this is a strictly defined workflow, which encompasses the use of a programming tool to define the workflow.

 When applying Machine learning to a workflow, or a supply chain, it is important to define the elementary activities (or smallest pieces) of the workflow process. These specific resources will often require pre-requisite activities, and define required resources. Combined with the Activities are various other types of “nodes”, including:

* Start (the logical beginning of the process)
* Actor or Activity (a block of code being executed without creating a decision)
* Split (a point where multiple processes can be created)
* Join (a point where multiple asynchronous requirements must converge)
* Decision (a point where only 1 possible successive edge may be activated)
* End (the logical end, or output, of the workflow)


 This is known as a common ADONIS workflow, and can be used to split workflow management into a variety of configurable steps. The ADONIS model is good for any adaptive workflow, and representing workflow actions that have been pre-configured or hard coded, however, it is also an ideal representation for workflow manipulation by AI systems.


 An example ADONIS workflow is shown above, illustrating the complex methodology used to execute various paths. It can be seen how changes to this operation may take months or years to perfect when performed through human intervention. Using a machine learning algorithm, this workflow can be managed in real-time due to the de-coupling of the activities and decisions.

 A ML algorithm will adapt two portions of the ADONIS workflow, one being the structure (the order of operations) and the other being the conditions. In a physical workspace, the use of condition induction through machine learning is often prominently available, although it requires the use of an automated shop floor controller. This process can not be utilized if a reliance on “Tribal knowledge” is present.

 One benefit to the use of an ADONIS system is the ability to mate the ML workflow with various cognitive automations. Each of the activities can be defined as cognitive automations, which require certain physical or data inputs, and define given outputs. The use of an ADONIS workflow means that activities can be developed separate from the workflow items themselves. This ability permits a Cognitive Automation (such as object identification) to be included in the process, without effecting other aspects. Other examples of Cognitive Automation being used to Augment a workflow may include Business critical decisions.

## Business Operations Requirements

 The “Black Box” of machine learning can contain a number of different algorithms which allow the proper “solution” or outcome to be identified. Different algorithms are utilized for differing business processes, however the inputs and training model for the system can often remain changed. From a business perspective, it is important to identify in advance what the most powerful data sources currently being utilized for human prediction are, and how those data sources can be consumed (reliably) to feed the “Black Box”. In order to determine those inputs sources, the first step is to identify the specific expected “solution” that is desired from the machine learning algorithm. Identifying a particular output will help to inform the development of the solution. A more generalized outcome will lead to more accurate results, but less optimization within those results. More exact expected outcomes will enable the machine learning algorithm to more granularly target the results.

 Once those data sources have been identified, the type of training (supervised, unsupervised, and reinforced) must be identified. In many cases, the first two training types can be augmented by reinforced data. Regardless of training type, a success criteria must be identified, so that the algorithm can accurately identify which “solutions” to the data can be considered successful, and which can be considered failures. In a scenario where reinforced learning is combined with supervised or unsupervised learning, this is strictly speaking defined as “deep learning”.

## SageMaker

>Amazon SageMaker is a fully managed service that enables you to quickly and easily integrate machine learning-based models into your applications


 The typical machine learning setup within SageMaker consists of a simplified machine learning lifecycle, designed to abstract the data management from the machine learning processes. In order to do this, SageMaker relies on the population of S3 buckets with the training data and model artifacts. The only code that needs to be created within SageMaker, is the model trainer, and the model “interpretation” layers. Both of these layers are specifically built using Amazon Elastic Container Registry (Docker).

 Data can be pulled from SageMaker using either a single persistent endpoint, or a batch transformation. These batch transformations can either be run on a schedule, or continually to update records based on new information that has been provided. In order to set up a single persistent endpoint, SageMaker Hosting Services must be utilized.

 SageMaker is designed to be used without any previous Machine Learning experience. This works no the principle that most machine learning algorithms are designed to be generically applied to data. SageMaker uses these generically designed algorithms to the dataset to produce the correct output.


## Proposed Solution

By breaking the currently workflow, which is strictly defined using the codebase, into a series of steps (or lambdas [Lambda Steps](https://quip-amazon.com/gE0UAh854Gco)) which have a pre-defined Input/Output based on a unified identifier and state ([Redesigned UI For FC](https://quip-amazon.com/QrEQA9UK5pWZ)), and a strictly defined dependency chain we can create the individual activities or actors present in an ADONIS workflow. Examples of these individual steps in our system would be “ASIN Flip”, “Change IOG”, or “Generic Label Printing” ([Label Maker](https://quip-amazon.com/ZmPMACbx0UZV)). Creating these individual actors removes the decision making process from the overall architecture. This would be the first step of creating a Machine Learning Cyber-Physical workflow.

The second set would be to transform our existing workflow and guidances into a training set, which can also be utilized as the initial configurations for the workflow. By breaking these workflows and guidances into single record sources ([Visual Device Reverse Logistics Workflow Manager](https://quip-amazon.com/eFJeAqPDmE5V)), we are able to create a “Decision” input, which accounts for the current state of input, and the appropriate values required for a future decision. These decisions can then be applied in the ADONIS workflow as the decision nodes, which will dictate the activities moving forward.

The Final step ([Intelligent Guidance](https://quip-amazon.com/xZJEAp7aakyx)) will be to create a SageMaker analysis to batch process our records, and create a trained model. This trained model will be able to view current workflow guidances from the training set, and use human intervention as the reenforcement. Workflows which are overridden, vetoed, or manually added to the set will continually improve the SageMaker data points.

Using this process, we will be able to offer **Intelligent Guidance** to manage an extremely large number of devices, as well as enable **Third Party** integrations to be introduced as new actors in the workflow. Utilizing SageMaker as a Machine Learning source will reduce the number of errors being created, since no new or altered Machine Learning algorithms must be directly created. The “Serverless” nature of SageMaker reduces the infrastructure burden at the same time, providing AWS levels of availability and dedicated GPU hardware to run Machine Learning tasks. Using a unified Data source for device state management will greatly reduce the number of operational errors that were introduced in previous architectures, and invalidate much of the existing **OE backlog**, which focuses on correcting pre-existing data issues.
