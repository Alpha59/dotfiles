## Standard Operating Procedure (SOP) for Point of Contact (POC)

This SOP outlines the responsibilities and procedures for the Point of Contact (POC) overseeing changes to the Pedigree system implemented by developers from a different team. The POC is accountable for ensuring that changes are correctly integrated, follow the team's coding processes, and meet the project requirements.

### Scope

This procedure applies to all POC activities related to overseeing changes to the Pedigree system by external developers.

### Responsibilities

* Ensure all changes align with the Pedigree system’s architecture and requirements.
* Provide guidance and answer questions from the developers.
* Review change requests (CRs) to ensure adherence to coding standards.
* Facilitate regular meetings to track progress and resolve issues.
* Document and track tasks and progress.
* Ensure developers adhere to the Pedigree system’s coding standards and best practices.
* Maintain documentation of decisions, changes, and project updates.

### Daily Responsibilities

1. Monitor Communication Channels:
    1. Check emails, Slack, or other communication tools for any queries or updates from the developers.
    2. Respond promptly to any questions or issues raised by the developers.
2. Review Change Requests (CRs):
    1. Review any submitted CRs for compliance with coding standards and project requirements.
    2. Provide feedback and request revisions if necessary.
3. Update Project Management Tools

    * Ensure that the status of tasks and user stories is up-to-date in project management tools (e.g: SIM, Confluence)

### Weekly Responsibilities

1. Bi-weekly Sync Meetings:
    1. Conduct bi-weekly sync meetings with the developers. These are one-hour sessions, held twice a week.
    2. Discuss progress, answer questions, and provide necessary guidance.
    3. Review current tasks, address blockers, and plan upcoming work.
2. Weekly Progress Summary:

    * Prepare a short summary of the week's progress, including completed tasks, current blockers, and planned activities for the next week.
    * Share this summary with relevant stakeholders.

### Monthly Responsibilities

1. Monthly Progress Update:
    1. Compile a comprehensive update summarizing the progress made over the month.
    2. Include completed milestones, ongoing tasks, identified issues, and plans for the upcoming month.
    3. Share this update with relevant stakeholders and document it in a shared, accessible location.
2. Milestone Tracking:
    1. Review and track the milestones published by the team.
    2. Ensure that the project is on track to meet these milestones and highlight any potential risks or delays.
    3. Update the milestone tracking document to reflect current status.
3. Documentation Maintenance:
    1. Review and update any relevant documentation to reflect changes, decisions, or new information.
    2. Ensure that all documentation is comprehensive and accessible to the developers and other stakeholders.

### Procedure

#### Initial Review and Documentation

* Thoroughly review all existing documentation related to the Pedigree system. This includes architecture diagrams, code standards, API specifications, and any other relevant materials.
* Identify any gaps or areas needing clarification to ensure a comprehensive understanding of the system.
* Create or update a reference document summarizing key points for easy access during meetings and reviews.

#### Initial Meeting

* Participate in the initial meeting to introduce yourself as the POC and outline your role.
* Present a high-level overview of the Pedigree system, emphasizing critical aspects relevant to the upcoming changes.
* Discuss and agree on communication channels, meeting schedules, and any initial concerns or questions from the developers.

#### Bi-weekly Sync Meetings

* Schedule bi-weekly sync meetings with the developers. These should be one-hour sessions, held twice a week.
* Use these meetings to discuss progress, answer questions, and provide any necessary guidance.
* Ensure the agenda includes reviewing current tasks, addressing blockers, and planning upcoming work.

#### Task Documentation

* Based on the initial review and ongoing meetings, document tasks in the form of user stories.
* Each story should include a clear description, additional context, and explicit acceptance criteria. Use the following template for user stories:

```
    [//]:# (This should be descriptive enough to frame the Story, at a high level, as well as include any additional resources needed to complete the Story.)

Should have *done something in the past tense to complete the story*
```

#### Progress Tracking

* Use project management tools (SIM) to monitor the progress of tasks and user stories.
* Regularly update the status of tasks and ensure all changes are documented.
* Highlight any risks or delays and discuss them in the bi-weekly sync meetings.

#### Question Resolution

* Be available to answer questions from developers during the bi-weekly meetings and via agreed communication channels (e.g., email, Slack).
* Provide detailed, clear, and prompt responses to facilitate progress.
* If necessary, escalate unresolved issues to higher management or subject-matter experts.

### Additional Responsibilities

**Code Responsibility**:

* Ensure the quality and correctness of the code being developed.
* Monitor adherence to the coding process, including code reviews, testing, and deployment procedures.
* While the POC is accountable for overseeing the code and the developers, **they are not expected to write any code themselves.**

**Communication and Coordination**:

* Maintain communication with all stakeholders, including developers, project managers, and other relevant teams.
* Coordinate with other teams as necessary to ensure smooth integration of changes.

**Documentation Maintenance**:

* Continuously update documentation to reflect any changes, decisions, or new information.
* Ensure that all relevant documentation is easily accessible to the developers and other stakeholders.

**Training and Support**:

* Provide necessary training or resources to developers to help them understand the Pedigree system and its requirements.
* Offer ongoing support to address any technical or procedural questions.

### Helpful Tips for Effective POC Management

**Preparation**:
Before agreeing to the POC role, ensure you have a thorough understanding of the Pedigree system and its documentation. Familiarize yourself with the team's coding standards and processes.

**Clear Communication**:
Establish clear communication channels and expectations with the developers from the beginning. Regularly check in to ensure everyone is aligned.

**Documentation**:
Keep comprehensive and up-to-date documentation. This will serve as a valuable resource for both you and the developers.

**Proactive Problem Solving**:
Anticipate potential issues and address them proactively. Encourage developers to raise concerns early.

**Feedback**:
Provide constructive feedback during code reviews and meetings. Recognize good work and suggest improvements where necessary.

**Time Management**:
Allocate sufficient time for meetings, reviews, and follow-ups.
Ensure that the bi-weekly meetings are productive and focused.


### Information to Know Before Agreeing to the POC Role

**Responsibility**:
Understand that you are accountable for overseeing the code and ensuring it meets the required standards. This includes guiding developers and reviewing their work, but not writing code yourself.

**Time Commitment**:
The role requires a ongoing time commitment, including regular meetings, reviews, and ongoing communication.

**Expertise**:
Ensure you have the necessary expertise and understanding of the Pedigree system and the coding standards to effectively oversee the changes.

**Support**:
Identify and confirm the support and resources available to you, such as access to subject-matter experts and relevant documentation.


### Review and Approval of Change Requests (CRs)

**CR Review**:

* As a mandatory reviewer, thoroughly review all CRs submitted by the developers.
* Ensure CRs comply with coding standards, architectural guidelines, and project requirements.
* Provide constructive feedback and request changes if necessary.
* Approve CRs only when they meet all criteria and standards.

### Summary

The POC is critical in ensuring the successful implementation of changes to the Pedigree system by external developers. By following this SOP, the POC will maintain clear communication, provide necessary guidance, and ensure adherence to coding and project standards.

### Documentation

All reviews, meeting notes, and progress updates should be documented and stored in a shared, accessible location (e.g., Confluence, SharePoint).

Adhering to this SOP will help streamline the process of integrating changes into the Pedigree system, ensuring consistency, quality, and successful project outcomes.
